# Turso Platform SDK (unofficial)

A TypeScript client for the [Turso Platform API](https://docs.turso.tech/api-reference/introduction):
manage organizations, databases, groups, members and Platform API tokens from code.

It is generated by the [Voxgig SDK generator](https://github.com/voxgig/sdkgen) from Turso's own
OpenAPI spec. This is not Turso's database client: to run SQL, use
[`@libsql/client`](https://docs.turso.tech/sdk/ts/quickstart). This SDK creates and deletes
databases, groups, tokens and members.

> Unofficial. Not affiliated with, endorsed by, or sponsored by Turso.
> Not published to npm. MIT licensed.
>
> Turso publishes an official TypeScript client for this same API,
> [`@tursodatabase/api`](https://www.npmjs.com/package/@tursodatabase/api); use that in production.
> This repository exists to evaluate the generator on Turso's spec, and its report is the main
> output.

## Install

From a clone (the compiled `dist/` is committed, so no build step is needed):

```bash
git clone https://github.com/omarmohelal/turso-platform-sdk
npm install ./turso-platform-sdk/ts
```

Needs Node.js 22.13 or later.

## Get a token

Platform API tokens are created with the [Turso CLI](https://docs.turso.tech/cli/introduction):

```bash
turso auth api-tokens mint my-token --org my-org
```

Keep it in an environment variable. The SDK sends it as `Authorization: Bearer <token>`.

## First call

```ts
import { TursoPlatformSDK } from '@omarmohelal/turso-platform-sdk'

const client = new TursoPlatformSDK({ apikey: process.env.TURSO_PLATFORM_APIKEY })

const databases = await client.Database().list({ organization_slug: 'my-org' })

for (const db of databases) {
  const { Name, primaryRegion, regions } = db.data()
  console.log(Name, primaryRegion, regions)
}
```

The snippet uses top-level `await`, so run it as an ES module (or inside an `async` function).
Every call returns entities; `.data()` gives the plain record. Operations throw on failure.

## What is covered

Turso's 53 operations are grouped into 20 entities:

| Entity | Operations | Actions (`create` with `$action`) |
|---|---|---|
| `ApiToken()` | create, list, remove | |
| `AuditLog()` | list | |
| `Database()` | create, list, load, remove | `restore`, `rotate`, `token` |
| `DatabaseConfiguration()` | list, update | |
| `DatabaseStat()` | list | |
| `DatabaseUsage()` | load | |
| `DeletedGroup()` | list | |
| `Group()` | create, list, load, remove | `restore`, `rotate`, `token`, `transfer`, `unarchive`, `update` |
| `GroupConfiguration()` | load, update | |
| `Instance()` | list, load | |
| `Invite()` | list, remove | |
| `Location()` | create, load, remove | |
| `Member()` | list, load, remove, update | |
| `Organization()` | create, list, load, update | `invite`, `member` |
| `OrganizationInvoice()` | list | |
| `OrganizationPlan()` | list | |
| `OrganizationSubscription()` | load | |
| `OrganizationUsage()` | load | |
| `User()` | load | |
| `Validate()` | load | |

Actions are operations on one database or group, for example minting a database token:

```ts
const result = await client.Database().create({
  $action: 'token',
  organization_slug: 'my-org',
  database_name: 'my-db',
})
const { jwt } = result.data()
```

The full reference, with every field and parameter, is generated in
[`ts/REFERENCE.md`](./ts/REFERENCE.md). On entities nested under an organization, its slug is
`organization_slug`. `Organization().load()` and `update()` take the slug as `id`.
`organization_id` appears only on the v3 endpoints, where it is Turso's internal organization ID.

## Example: organization summary

[`examples/org-summary.ts`](./examples/org-summary.ts) prints who the token belongs to, the
organization's databases (group, regions) and its groups. It only reads. It runs the `.ts` file
directly, so it needs Node.js 24 (tested on 24.21).

```bash
cd examples
# examples/.env.local (gitignored):
#   TURSO_PLATFORM_APIKEY=...
#   TURSO_PLATFORM_ORG=my-org
npm run summary
```

Its tests run against the SDK's offline mock (`TursoPlatformSDK.test()`), with no network:

```bash
cd examples && npm test
```

## Run the tests

```bash
cd ts
npm install
npm test
```

The suite is offline: the SDK swaps its HTTP transport for an in-memory mock. It includes a check
of every operation against the OpenAPI spec (`test/definition.test.ts`) and runs the code blocks
in `ts/README.md` and `ts/REFERENCE.md`.

The generator can also produce a live suite (`TURSO_PLATFORM_TEST_LIVE=TRUE`). It creates, updates
and deletes real resources, so it was not run for this repository.

## Regenerate

Generation needs Node.js 24 or later.

```bash
cd .sdk
npm install
npm run generate
npx voxgig-sdkgen doctor
```

What is yours to edit:

- `.sdk/def/turso-openapi.json` — Turso's spec, unmodified (source and sha256 in `.sdk/def/README.md`)
- `.sdk/model/guide/guide.aontu` — corrections to how paths became entities
- `.sdk/model/project.aontu` — publisher, package name, README text

Everything under `ts/` is generated and overwritten on every run.

On Windows, generation needs `./` in front of local includes
([create-sdkgen#62](https://github.com/voxgig/create-sdkgen/issues/62)); that change is already
in `.sdk/model/sdk.aontu` and `.sdk/test/test.aontu`. If you scaffold a new project on Windows,
`npm create @voxgig/sdkgen` also stops at its own `npm install`
([create-sdkgen#58](https://github.com/voxgig/create-sdkgen/issues/58)); run `npm install` in
`.sdk` yourself. Details in the report.
